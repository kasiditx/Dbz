# T-004a same-workload experiment

Throwaway prototypes, synthetic data only. No DB connections. ADR-0001 Pending; ADR-0002 Proposed.

## Build

```sh
export PATH=/opt/homebrew/opt/rustup/bin:$PATH
cargo build --release --locked --manifest-path crates/poc-ui/Cargo.toml
cd crates/poc-tauri
npm ci --ignore-scripts
npm run release
# Local experiment only: ad-hoc sign the produced bundle; no distribution identity.
codesign --force --sign - 'src-tauri/target/release/bundle/macos/Dbz Tauri POC.app'
```

No dev server is used for decision evidence. `npm run release` embeds built Vite assets in the Tauri executable.

## Workload

`workload.json` + `query.sql`: 1280×800 **content area**, 1K/100K/1M rows, 20 columns, 22 px rows, 150 px columns (NOTES 320 px), 3 SQL tabs, 400 ms mock delay. Large SQL = script repeated 500 times. Rust generator: `crates/poc-workload`; TypeScript port: `crates/poc-tauri/src/model.ts`. Decimal strings never converted to float. NULL, Thai, Japanese/Greek, timestamps, two long-text columns. No rows stored eagerly; TanStack still has O(N) metadata.

Egui `--comparison` opts into shared data/SQL/tabs, retaining the original T-003 default. Tauri is always this workload. Tauri native height is 832 on this macOS (32 px chrome → 800 content); egui requests 800 inner size. Check raw dimensions before claiming a match.

## Measurement

```sh
python3 benchmarks/t004a/harness.py env
python3 benchmarks/t004a/harness.py startup
python3 benchmarks/t004a/harness.py idle --stack tauri --rows 100000 --label idle-tauri-100k-1 --seconds 65
python3 benchmarks/t004a/harness.py active --stack tauri --rows 1000000 --label active-tauri-1m-1 --seconds 120 --large-sql
```

Harness starts both through LaunchServices (`open -n -W`, same stdout-ready polling). Egui executable is copied without modification into a local `.app` under its ignored target directory. This establishes an app identity for helper ownership. Readiness is six UI/rAF callbacks with UI mounted, **not verified display presentation**. Polling adds ≤5ms quantization. Keep all runs, including first cache/outlier runs. No cold-cache purge; cold startup NOT MEASURED.

Idle has no continuous rAF/repaint loop; samples at 1 Hz after READY, evaluate last samples at ≥60 s. CPU uses cumulative CPU-time delta over the sample interval, not `ps %cpu`. Active captures per-frame intervals continuously, so active CPU is a diagnostic continuous-repaint workload. DOM counting adds overhead; reported as instrumented release.

Input actions are performed through `cua_repl` against actual desktop apps. Save the action log and app state snapshots. A CUA API-call timestamp includes automation transport/activation overhead: report **CUA-call→observed app-state upper bound**, not precise OS-event dispatch latency. Input-to-display is NOT MEASURED. No comparison between egui `ui()` CPU and React commit CPU is valid. React CPU/JS CPU stages remain unmeasured in ordinary release.

Memory candidates alone are NOT an attributed group. Require ownership evidence from `ownership.py`; keep main-only RSS separate, reject unrelated helpers, flag unknown attribution. Sum RSS may double count shared mappings. Physical footprint is a separate optional diagnostic, not substituted for RSS.

Exploratory `exploratory-startup-direct.json` used direct executables and mismatched content height; excluded from final comparison.

## Deterministic native input sequence

Start `harness.py active --large-sql --seconds 120` for a stack/dataset. In `cua_repl`, bind the running bundle with `cua.getApp`, import `cua-workload.mjs`, then call `runPhase(app, fs, absoluteRawDirectory, phase)` sequentially for `grid-key`, `tab-switch`, `large-sql-typing`, `scroll`, `resize` (separate tool calls keep each batch below the host timeout). It sends 20 Down keys, 20 Ctrl+Tab switches, 20 ASCII inserts in the large script, 20 mouse scroll calls, and six real right-edge drags alternating −160 and +160 logical pixels in width. Geometry derives from the actual app state and JPEG/PNG screenshot. Each phase uses predetermined inputs, then refreshes the accessibility state; it does not synthesize events outside CUA. Preserve all failed matches. Run one stack at a time; do not run compilers or interact with other windows during idle measurement.

The Python harness never injects UI input. Raw screenshot/AX/state/action files are generated by the CUA driver. A script is included for repeatability; it is not a claim of fully unattended cross-platform CI.

`analyze.py` uses nearest-rank percentiles, retains outliers, and writes `raw/summary.json`. `cells.json` is a shared language-neutral example fixture consumed by both Rust and TypeScript tests. Missing cold/precise latency/platform measurements remain gaps.

The CUA driver records its actual high-level scroll calls and drag endpoints. Legacy `scrollNotches`/`resizeSteps` fields in the initial JSON describe the earlier CGEvent reference schedule; CUA does not expose those low-level event counts. They are not claimed as measured wheel deltas/drag steps. Both stacks receive the same CUA schedule.

Each sample label must be new: harness rejects labels with existing raw artifacts to prevent stale frame/footprint reuse. Interrupted exploratory runs are retained under `exploratory-*` and excluded from final aggregation. Warm startup performs one separate prewarm per stack, then ten measured alternating runs; the earlier unconditioned series is retained in `startup-before-preconditioning.json`.
